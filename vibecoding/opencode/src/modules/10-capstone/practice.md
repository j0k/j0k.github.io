# Модуль 10 — Практика и сдача капстоуна

**Время:** 10 часов · **Артефакт:** `labs/10-capstone/`

---

## Чек-лист выполнения

### Подготовка

- [ ] Задача выбрана и согласована (3–10 файлов, проверяемый результат).
- [ ] Ветка создана: `git checkout -b capstone/<название>`.
- [ ] `AGENTS.md` актуален.

### Спека

- [ ] `labs/10-capstone/spec.md` заполнен по шаблону.
- [ ] 5+ требований, каждое проверяемо.
- [ ] Критерии приёмки — конкретные команды.
- [ ] Есть блок «не входит в задачу».

### План

- [ ] `labs/10-capstone/plan.md` — 4–8 шагов.
- [ ] Для каждого шага: файлы, проверка, риск.
- [ ] План утверждён до начала кодирования.

### Реализация

- [ ] Каждый шаг — отдельный коммит.
- [ ] `git log --oneline` читается как история изменений.
- [ ] `./scripts/check.sh` зелёный на HEAD.
- [ ] Ни один шаг не потребовал > 2 итераций без отката.

### Ревью

- [ ] `labs/10-capstone/review.md` — чек-лист заполнен.
- [ ] Есть второе мнение (другая модель/субагент).
- [ ] Все замечания: исправлены или обоснованно отклонены.

### Мерж

- [ ] PR-описание: что/почему/как проверено.
- [ ] CI зелёный.
- [ ] Дифф прочитан целиком (подтвердите: «прочитал, N строк»).
- [ ] Нет `skip`, `xfail`, `TODO`, `print` в новом коде.

### Ретро

- [ ] `labs/10-capstone/retro.md` по шаблону.
- [ ] Метрики заполнены реальными числами.
- [ ] Сформулировано одно правило на будущее.

---

## Формат сдачи

```
labs/10-capstone/
├── spec.md
├── plan.md
├── review.md
├── retro.md
└── links.md      ← ссылка на PR/ветку + git log --oneline
```

---

## Защита (10 минут)

1. 2 мин — задача и спека.
2. 3 мин — план и почему именно такой.
3. 3 мин — **обязательно**: место в диффе, где вы отклонили предложение агента,
   и почему.
4. 2 мин — метрики и вывод.

Без пункта 3 капстоун не зачитывается: значит, ревью было формальным.
