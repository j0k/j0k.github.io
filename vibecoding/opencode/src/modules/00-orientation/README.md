# Теория

## 1. Что такое вайбкодинг (и чем он не является)

**Вайбкодинг** — это разработка, в которой значительную часть кода пишет агент, а человек
выполняет роль постановщика задачи, ревьюера и владельца результата.

Это **не** «нажал кнопку — получил продукт». Это смена распределения труда:

| Раньше | Теперь |
| --- | --- |
| вы пишете код | вы пишете спеку и проверку |
| вы помните API | вы проверяете, что API существует |
| ошибка = опечатка | ошибка = уверенно написанная неправда |
| скорость = набор текста | скорость = качество контекста |

Ключевой сдвиг: **узкое место переместилось из набора кода в постановку задачи и проверку.**

## 2. Три роли

Работают только вместе:

```
Постановщик  →  что делаем, зачем, как проверим
Агент        →  быстрый исполнитель, не знает вашего контекста
Ревьюер      →  читает дифф, ловит вранье, коммитит
```

Если вы совмещаете все три и экономите на ревью — вы получаете скорость написания
и скорость накопления долгов одновременно.

## 3. Где агент силён и где проваливается

**Силён:**
- шаблонный, типовой код (CRUD, конфиги, тесты по образцу);
- перевод между языками и библиотеками;
- объяснение чужого кода;
- массовые однотипные правки.

**Проваливается:**
- незнакомый внутренний контекст («как у нас принято»);
- длинные цепочки требований без проверки;
- точные версии API, которых нет в обучающих данных;
- задачи, где «правильно» = «так решил бизнес», а не «так принято в интернете».

Вывод: отдавайте агенту то, что можно проверить, и оставляйте себе то, что требует суждения.

## 4. Модель — не главный фактор

Порядок влияния на результат:

```
контекст и постановка  >  наличие проверки  >  итеративность  >  модель  >  формулировка промпта
```

«Волшебные слова» вроде «подумай пошагово» дают эффект на порядок меньше,
чем один правильно приложенный `AGENTS.md` и работающий тест.

## 5. Инструменты

OpenCode — CLI-агент: читает файлы, правит их, запускает команды, спрашивает разрешения.

Три сущности, которые надо знать с первого дня:

| Сущность | Зачем |
| --- | --- |
| **Сессия** | один рабочий контекст; новая задача — новая сессия |
| **Permissions** | что агенту можно без спроса, что нельзя вообще |
| **Модель** | выбирается под задачу, а не «одна на всё» |

## Чек-лист понимания

Ответьте себе, не подглядывая:

1. Почему узкое место сместилось из набора кода в постановку задачи?
2. Назовите три типа задач, где агент стабильно слабее человека.
3. Почему экономия на ревью диффа — плохая экономия?
4. Что даёт больший прирост: смена модели или `AGENTS.md`? Почему?
